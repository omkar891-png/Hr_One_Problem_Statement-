# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period logic uses `minutes > 10` after integer truncation of `total_seconds / 60`. At 09:40:01 (for a 09:30 shift), `total_seconds = 601`, `int(601 / 60) = 10`, so `10 > 10` evaluates to False, returning 0 instead of 10. Violates R2 strict threshold (>10:00). | Punch-in at 09:40:01 IST for shift 09:30 returns 0 late minutes instead of 10. | Changed condition to test seconds strictly: `diff_sec > 600`, returning `int(diff_sec // 60) if diff_sec > 600 else 0`. |
| 2 | `compute_late_minutes` (lines 33-37) | Replaces hour and minute directly on `punch_in` datetime without converting to IST or considering overnight shifts. If `punch_in` is UTC, subtracting IST shift start hour produces wrong negative or offset values. Also, for overnight shifts starting on day D with punch-in on day D+1, it constructs the shift start on D+1 in the future. | An overnight shift punch-in at 00:05 IST on day D+1 for a 22:00 shift computes shift start as D+1 22:00, producing a negative delta instead of 125 late minutes. | Standardized `punch_in` to IST aware datetime and anchored shift start to the attendance record's IST calendar date. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round(..., 2)` which performs banker's rounding (round half to even). Rule R4 explicitly mandates half-up rounding. For example, 2.125 rounds to 2.12 with banker's rounding, but must be 2.13. | Work duration of 2.125 hours (7650 seconds) returns 2.12 instead of 2.13. | Implemented half-up rounding using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (lines 44-47) | Missing the 30-minute qualification threshold. Rule R3 specifies overtime is counted only if minutes from shift end to punch-out is at least 30, otherwise 0. Starter returns `max(0, minutes)`. | Punching out 15 minutes after shift end returns 15 overtime minutes instead of 0 (Sample 1 notes 5 min overtime yields 0). | Added check `minutes if minutes >= 30 else 0`. |
| 5 | `compute_overtime` (lines 44-47) | Constructs shift end with `tzinfo=IST` while `punch_out` from PyMongo or client is naive UTC, raising `TypeError: can't subtract offset-naive and offset-aware datetimes`. Also, for overnight shifts (`shift_end <= shift_start`), `shift_end` is on the next calendar day (`date + 1 day`), which was ignored. | Calling `compute_overtime` with a naive datetime crashes with `TypeError`. Overnight shift overtime is computed against the start day instead of next day. | Ensured both datetimes are timezone-aware in IST/UTC, and advanced `shift_end` by 1 day when `shift_end <= shift_start`. |
| 6 | `health` (lines 72-74) | Lacks MongoDB ping probe. The contract specifies returning 200 only when MongoDB answers a ping, otherwise 503. Starter returns 200 unconditionally. | Stop MongoDB service; `GET /health` still returns 200 `{"status": "ok"}` instead of 503. | Added `client.admin.command('ping')` inside a try/except block; raises `HTTPException(503)` if ping fails. |
| 7 | `create_employee` (lines 77-85) | Check-then-insert race condition. Two concurrent requests with the same `emp_code` both pass `find_one` and both call `insert_one`. | Sending parallel POST requests for the same `emp_code` results in duplicate records or unhandled database errors. | Created a unique index on `emp_code` at startup and handled `pymongo.errors.DuplicateKeyError` by raising HTTP 409. |
| 8 | `create_employee` (lines 77-85) | Sets `doc["created_at"] = datetime.now()`, which FastAPI serializes as an ISO string. The contract and DATA_MODEL.md require `created_at` to be integer epoch milliseconds in the API and BSON UTC datetime in MongoDB. | The response body returns `"created_at": "2026-01-05T04:30:00"` instead of an integer epoch milliseconds like `1783312500000`. | Stored UTC BSON datetime in MongoDB and converted `created_at` to integer epoch milliseconds in the response. |
| 9 | `create_employee` (lines 53-61, 77-85) | Missing validation for shift times and employee code formatting. Schema requires `shift_start` must differ from `shift_end` (422 if equal), and `emp_code` must match `^EMP\d{4,6}$`. | Creating an employee with `shift_start == shift_end` or an invalid code like `"ABC"` returns 201 instead of 422. | Added Pydantic field validators and regex patterns to reject equal shift times and malformed codes with 422. |
| 10 | `list_employees` (lines 88-96) | Pagination skip off-by-one error. Starter calculates `skip = page * page_size`. Since `page` is 1-indexed (default page 1), `skip` evaluates to 20 for page 1, skipping the first page of results entirely. | Requesting `GET /employees?page=1` returns items 21-40 rather than items 1-20. | Updated skip calculation to `skip = (page - 1) * page_size`. |
| 11 | `list_employees` (lines 88-96) | Total count ignores filter. Starter executes `total = db.employees.count_documents({})`, returning the total collection size rather than matching documents. Rule R10 mandates total reflects applied filters. | Requesting `GET /employees?department=Engineering` returns `total` equal to all employees in the database. | Changed to `total = db.employees.count_documents(q)`. |
| 12 | `list_employees` (lines 88-96) | Missing required sort order. Contract states employees must be sorted by `emp_code` ascending. Starter does not specify a sort order. | Employees are returned in non-deterministic or insertion order rather than sorted by `emp_code`. | Added `.sort("emp_code", 1)` to the query cursor. |
| 13 | `list_employees` (lines 88-96) | Unconverted `created_at` in items. Documents fetched from MongoDB contain BSON datetime objects which serialize to ISO strings instead of epoch milliseconds. | `items[].created_at` in `GET /employees` contains string timestamps instead of integers. | Converted `created_at` to epoch milliseconds for each item. |
| 14 | `punch_in` (lines 99-122) | Unhandled 500 crash on non-existent employee. If `db.employees.find_one(...)` returns `None`, line 113 accesses `emp["shift_start"]`, throwing an uncaught `TypeError`. | Calling `POST /attendance/punch-in` with an unknown `emp_code` crashes with 500 Internal Server Error instead of 404. | Added `if not emp: raise HTTPException(404, "Employee not found")`. |
| 15 | `punch_in` (lines 99-122) | Check-then-insert race condition. Simultaneous punch-in requests for the same employee and date both pass `find_one` and attempt insertion. | Concurrent punch-ins create multiple records for the same employee and date. | Created a compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 16 | `punch_in` (lines 99-122) | Attendance date calculation ignores IST and overnight shifts (R1). Starter uses `datetime.fromtimestamp(body.punched_at / 1000)` in local server time and does not apply the rule that overnight shift punch-ins before `shift_end` belong to the previous day. | An overnight shift (22:00 - 06:00) punch-in at 00:30 IST is assigned to the current calendar date instead of the shift start date. | Implemented R1 attendance date logic using IST timezone and shift bounds. |
| 17 | `punch_in` (lines 99-122) | Missing instant truncation to whole seconds (R1). R1 specifies: "Before any calculation, instants are truncated to whole seconds (09:40:00.900 counts as 09:40:00), and the truncated value is stored and returned." Starter preserves sub-second precision. | Passing `punched_at: 1783312500900` stores and returns milliseconds `900` rather than `000`. | Truncated epoch milliseconds via integer division: `(ms // 1000) * 1000`. |
| 18 | `punch_in` & `list_attendance` (lines 119, 149) | Returns internal MongoDB `id` on attendance records (`doc["id"] = str(res.inserted_id)`). Contract and DATA_MODEL.md explicitly specify records have no `id` and are addressed by `(emp_code, date)`. | Attendance records contain an unauthorized `"id"` field, violating OpenAPI schema contract. | Removed `"id"` and `"_id"` from all response records. |
| 19 | `punch_in` (lines 63-67) | Missing status validation. Only `PRESENT`, `WFH`, and `ON_DUTY` are permitted at punch-in. Starter allowed any string. | Submitting `status: "ABSENT"` or invalid strings at punch-in returns 201 instead of 422. | Constrained status to `PresenceStatus` literal enum in the request model. |
| 20 | `list_attendance` (lines 125-150) | In-memory loading and sorting loads the entire matching dataset into Python memory (`docs = list(db.attendance_logs.find(q))`), causing severe latency and memory exhaustion at 100,000 records. | Requesting `GET /attendance` with 100k records causes extreme response times and Out Of Memory errors. | Replaced in-memory sorting and slicing with MongoDB cursor `.sort(...).skip(...).limit(...)` and `.count_documents(q)`. |
| 21 | `list_attendance` (lines 125-150) | Incomplete sort order. Contract requires records sorted by `date` descending, then `emp_code` ascending. Starter only sorted by `date` descending. | Multiple records on the same date appear in non-deterministic order. | Added secondary sort on `emp_code`: `.sort([("date", -1), ("emp_code", 1)])`. |
| 22 | `list_attendance` (lines 125-150) | Missing date range validation. Contract specifies `date_from > date_to -> 422`. Starter did not check this. | Requesting `?date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty items instead of 422. | Added check: `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 23 | `list_attendance` (lines 125-150) | Unconverted BSON datetimes in attendance listing items. Datetimes inside documents (`punch_in`, `punch_out`, `history[].at`) are returned as datetime objects, serializing to ISO strings. | Response items have string dates instead of integer epoch milliseconds. | Converted all BSON datetimes in records and nested history entries to epoch milliseconds. |

Also note anything you looked at and decided was **not** a defect, and why:
- **`load_dotenv()` behavior**: Calling `load_dotenv()` without `override=True` ensures that real environment variables injected by the test runner take precedence over any local `.env` file, adhering to the environment contract.
- **Using `emp_code` instead of MongoDB `_id`**: The absence of `_id` in API bodies is intentional per the specification; `emp_code` is the business identifier everywhere.
- **Absence of an `id` attribute on attendance records**: Attendance records are addressed exclusively by the composite natural key `(emp_code, date)` without a synthetic identifier.
- **`history` omission on punch-in / punch-out**: Punch events are original occurrences and must not write to `history`; `history` is reserved strictly for manual corrections (regularizations).
